# Unit 6: Two SDKs (Python + TypeScript) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the backend Python SDK and the frontend TypeScript SDK as method-for-method mirrors over contract v1, closed by an end-to-end smoke: submit → stub execution → events stream back through the SDK.

**Architecture:** Each SDK is a thin handle layer (`client` → `session` → `run`) over the six HTTP endpoints. `wait()` polls `GET /v1/runs/{id}` — the log-tail truth, so a run whose wire events were missed still resolves at the wait boundary. `stream()` parses SSE, dedups persistent events by a per-run seq watermark, and auto-reconnects with the last cursor on transport drops. Identity is a bare key; the temp-key surface (`user=`) is unit 17.

**Tech Stack:** Python 3.13 + httpx 0.28 sync client (already in requirements-dev, no new deps); TypeScript 5.7+, tests run on Node 24 native type-stripping (`node --test`), dist built by tsc.

**Spec:** docs/02-sdk-contract.md (SDK semantics), contract/openapi.yaml (wire shapes), docs/05-execution-and-streaming.md §4 (SSE: cursor `run:seq`, state keepalive, possible repeats).

## Global Constraints

- Comments/logs/commits in English (AGENTS.md); code follows DRY / no-over-defense rules there.
- Python SDK is sync-only this unit — the async surface arrives with its first consumer. No new Python dependencies.
- SDK unit tests run against a local in-process fake server speaking the real wire shapes — no DB, no manager import. The one live test lives in `manager/tests` (existing harness). Tests never touch a non-`*_test` DB (root conftest enforces).
- Root `pyproject.toml` gains `sdk/python/src` in `pythonpath` and `sdk/python/tests` in `testpaths`; ruff line-length 120 applies.
- TS: relative imports carry explicit `.ts` extensions; tsconfig uses `rewriteRelativeImportExtensions` so `dist` emits `.js`. Dev deps only `typescript` + `@types/node` (`node_modules/` already gitignored). The smoke script uses zero deps (global fetch).
- Client constructors: Python `create_client(key, *, base_url, poll_interval=0.5, reconnect_delay=1.0)`; TS `createClient(key, { baseUrl, pollIntervalMs = 500, reconnectDelayMs = 1000 })`. `wait` timeout is seconds in Python, milliseconds in TS.
- Error mapping by HTTP status: 401→Auth, 404→NotFound, 409→Conflict, 422→Contract; anything else→base error. All carry code+message from the `{"error": {...}}` envelope.

## Review Focus

1. **SSE frames split across chunk boundaries** — a `data:` line arriving in two TCP chunks must reassemble into one frame. Pinned in Task 3 (py) and Task 6 (ts) via a fake server that writes split raw bytes.
2. **HTTP error status on the events endpoint** (404 wrong session) — the SDK raises the mapped error immediately and must NOT enter the reconnect loop. Pinned in Task 3 / Task 6 (assert the fake saw exactly one request).
3. **Duplicate replay after reconnect** (subscribe-before-replay race) — the seq watermark suppresses events the consumer already saw. Pinned in Task 3 / Task 6.
4. **`wait()` on an already-terminal run resolves on the first poll** — no sleep before the first fetch, exactly one GET. Pinned in Task 4 (py) and Task 5 (ts).
5. **Idempotent submit replay (HTTP 200)** returns the same run handle without raising. Pinned in Task 2 (py) and Task 5 (ts).

### Task 3: Python stream()

**Files:**
- Modify: `sdk/python/src/agentops/http.py` (SSE frame parser), `client.py` (stream)
- Test: `sdk/python/tests/test_stream.py`

**Interfaces:**
- Consumes: `Http`, `Event` (defined here): dataclass `Event(type: str, run_id: str | None, seq: int | None, data: dict)`.
- Produces: `Http.events(path: str, params: dict) -> Iterator[tuple[str | None, dict]]` — GET, raises mapped `HttpError` on non-200 status before streaming; yields `(frame_id, payload)` per SSE frame (`id:`/`data:` lines, blank line ends a frame, lines may split across chunks; ignores `event:`/comment lines).
- Produces: `Session.stream(*, from_run=None, from_seq=None) -> Iterator[Event]` — first connect passes the caller's cursor (omitted when `from_run` is None); yields state frames as `Event("state", None, None, data)` and updates `Session.current_run` from `data["run"]`; per-run seq watermark skips already-seen events; tracks the last yielded `(run_id, seq)`; on transport drop (`httpx.TransportError` **or** `httpx.RemoteProtocolError` — server close mid-stream is the latter) sleeps `reconnect_delay` and reconnects with the cursor; HTTP error statuses raise immediately, no retry.

  - explicit `from_run`/`from_seq` reach the query string.
