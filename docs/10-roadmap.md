## 1. 路线图

| 里程碑 | 内容 |
|---|---|
| M1 | 协议定义 + 共享 spec 模型 + 校验器 |
| M2 | `config`：`iam`（账号、成员、邀请、配额）+ `audit` 领域 |
| M3 | `config`：`tool` + `skill` 领域 + 管理 API |
| M4 | `config`：`secrets` 领域（凭据加密、取用、管理 API） |
| M5 | `config`：`agent` 领域（ReAct）+ `release` 领域 |
| M6 | `runtime`：ReAct 编译与执行 + HTTP 工具 + 运行日志 |
| M7 | `gateway` + 事件推流与断线重连 + 后端 Python SDK |
| M8 | Python 工具沙箱 |
| M9 | Skill 渐进加载 |
| M10 | `config`：DAG 编辑 + `runtime` DAG 编译 |
| M11 | 子 Agent（声明、环检测、嵌套运行） |
| M12 | 前端 TypeScript SDK |
| M13 | 观测：运行日志查询、成本 |

覆盖 M1–M13，规模超出单个实现计划。**每个里程碑应产出各自独立的实现计划**，按顺序推进；M1 是其余一切的前置依赖。

## 2. 待定项

1. **DAG 的编辑形态。** v1 用表单与 JSON 编辑图结构，不做拖拽画布。但图一旦超过十来个节点，手写边就不现实了 —— **画布什么时候补，取决于第一个真实 DAG 的规模**。
2. **账号的口令形式。** 账号体系本身已经定了 —— 平台级账号、邀请加入、开租户是运维动作（见 [03-domain-model.md](./03-domain-model.md) 2.6）。未定的是**口令怎么存**：本地校验，还是接一个轻量目录。v1 不做单点登录。
3. **权限模型何时升级到工具级。** 触发条件：第一个外部调用方调用一个会写外部系统的 Agent。见 [09-permissions.md](./09-permissions.md) 第 3 节。
4. **永久 key 何时放开成多把。** v1 一个 Agent 一把，所有后端调用方共用，出了事分不清是谁。放开成多把（每把可命名、可单独停用）的时机，取决于第一次出现"同一个 Agent 被多个外部系统调用、且需要区分"的场景。见 [09-permissions.md](./09-permissions.md) 2.1。
5. **凭据的主密钥怎么托管与轮换。** 凭据在库里加密存储，靠部署环境里的一把主密钥（见 [08-credentials.md](./08-credentials.md) 第 4 节）。**轮换主密钥意味着把全部凭据重新加密**，这个操作没有方案；将来多环境部署时，托管方式也要重定。
6. **发布是否需要审批流。** 失去 Git PR review 后，如果仍需要"变更需批准"，建议在发布领域加可选的审批步骤。
7. **子 Agent 嵌套深度上限取多少。** 环检测保证无环，但不保证浅。建议 8 层，具体值应等真实嵌套场景出现后再定。见 [04-orchestration.md](./04-orchestration.md) 第 4 节。
8. **读模型的更新方式。** 同步触发（与写同事务）还是异步事件驱动？前者简单但写入变慢，后者快但有延迟。
9. **ReAct 的可解释性如何缓解。** 灵活性带来的不可解释性只能缓解、不能消除。可选做法：在运行日志里额外记录每轮的工具选择理由。这能回答"它做了什么"，但回答不了"它为什么没做另一件事"。见 [04-orchestration.md](./04-orchestration.md) 1.2。
10. **哪些流程该从 ReAct 迁到 DAG。** 有了两种模式，"什么时候该迁"就成了一个真实的运维决策 —— 迁移的判据、由谁判定、迁移时怎么保持行为一致，目前没有标准。见 [04-orchestration.md](./04-orchestration.md) 1.3。
11. **生产环境的日常变更是否改走数据库。** 环境稳定之后，变更可能主要靠直接的 SQL 变更，平台的编辑与发布退化为测试与应急手段（见 [06-release.md](./06-release.md) 第 3 节）。**这条路绕开版本、审计与快照** —— 改了库里的行，不产生新版本、不进审计、不更新发布记录。届时得先回答"怎么记录、怎么防止漂移"，v1 不设计。
12. **步骤重试的上限与退避。** 重投是 at-least-once，未完成的那一步会被重试（见 [05-execution-and-streaming.md](./05-execution-and-streaming.md) 第 5 节）。超过上限就把 Run 判失败 —— 具体几次、要不要退避，等真实故障率出来再定。
