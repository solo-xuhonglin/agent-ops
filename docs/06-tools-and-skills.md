## 1. 工具

### 1.1 形态

| 类型 | 执行方式 | 关键约束 |
|---|---|---|
| HTTP 工具 | `runtime` 直接发起请求 | 参数模板、参数占位符解析、超时与有限重试、**响应裁剪**（防止大响应撑爆上下文） |
| Python 工具 | 一次性容器 | 镜像**预构建**；网络默认**完全禁用**；只读根 + 可写输出目录；CPU/内存/磁盘/墙钟限额；stdin/stdout 走 JSON |

> **运行时不做依赖安装。** 加工具需要走一次镜像构建流程。这是刻意选择：运行时装依赖既是安全漏洞也是性能灾难。

### 1.2 凭据

工具的认证信息**不写在工具里**。工具只声明它需要一份凭据，用哪一份由 **Agent 挂载时**决定 —— "以谁的权限调外部系统"因此跟着 Agent 走。

凭据是**租户登记的外部账号**（Agent 在外部系统里的专用身份），加密存储，明文不落库。详见 [07-credentials.md](./07-credentials.md)。

## 2. Skill

### 2.1 渐进加载

类渐进披露机制：Skill 的**名称与描述**总是注入系统提示（开销很小），全文只在需要时由模型通过内置工具拉取，拉取后进入会话上下文并可缓存。

因此绑定几十个 Skill 也不会撑爆上下文。**描述字段是必填的** —— 渐进披露完全依赖它来判断该不该拉取正文，缺了它这个机制就失效。

---

## 3. 版本

Tool 与 Skill **独立版本化**，与 Agent 一样走 `release` 域。

Agent 发布时，快照里记的是**挂载到的版本号**，不是"当前最新" —— 所以改一个 Tool 不影响已发布的 Agent，除非把它重新发布（见 [05-release.md](./05-release.md) 第 1 节）。
